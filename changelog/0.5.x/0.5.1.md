# 0.5.1 — 2026-11-03

## Added

- **`containerTitles`** on `crossref_get_work` and each `crossref_search_works` work — every container title in deposited order; `containerTitle` stays the first, and the container line in `content[]` joins them with ` | ` (#93).
- **`memberId`** (number) on `crossref_get_work` and each `crossref_search_works` work — the Crossref member that holds the DOI now. `member` joins the `crossref_search_works` `fields` enum. The `crossref_get_member` and `crossref_get_prefix` descriptions route through `memberId`: a prefix names its registrant, which for a transferred title is not the member holding its DOIs (#94).
- **`descendants`** on a `crossref_search_funders` `funder_doi` lookup — the registry IDs of the funder's descendants, present only when non-empty, with a `**Descendants (N):**` line. Name-query rows are unchanged (#95).

## Changed

- **Page-size caps are set per input** — `rows` on `crossref_search_works` 100 → 250, on `crossref_search_journals` 100 → 500, on `crossref_search_funders` 100 → 1000 (its schema maximum, so no longer clamped); `limit` on `crossref_get_work` 500 → 10000 and on `crossref_get_references` 500 → 2500. `authorLimit`, the defaults, and the schema maxima are unchanged (#96).
- **A page near an offset ceiling returns the rows that fit** — when `offset + rows` would pass the route's ceiling (10,000 on `crossref_search_works` and both works lists, 100,000 on journal and funder name search), the page returns the rows that fit with a notice naming the rows requested and applied. `offset_too_large` and `works_offset_too_large` now fire only at or past the ceiling; their `data` no longer carries `rows` and their messages are reworded. `nextOffset` and `nextWorksOffset` are handed out below the ceiling (#96).
- **Every works list sends `select=`** — `crossref_search_works` sends its 20 summary fields when `fields` is omitted or empty, and the journal and funder works lists send the 7 fields their summaries read. Tool output is unchanged (#96).

## Fixed

- **`crossref_search_journals` `include_works` reads every ISSN on the matched record** — one `/works` request with an `issn:` pair per distinct ISSN, in place of `/journals/{issn}/works` for the one ISSN Crossref filed the record under, so `recentWorks` and `worksTotal` no longer undercount. A record whose ISSN entries are all malformed skips the works lookup with the existing notice, now worded "no well-formed ISSN registered" (#90).
- **`content[]` keeps a trailing `#` run in a heading and a trailing `\` at line end** — both are escaped, so the Markdown parses back to the `structuredContent` value. Affects the headings of `crossref_get_work`, `crossref_get_member`, `crossref_search_works`, `crossref_search_journals`, and `crossref_search_funders` (#91).
