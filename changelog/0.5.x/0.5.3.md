# 0.5.3 — 2026-11-14

## Added

- **`facets`** on `crossref_search_works` — any of Crossref's 21 facet names mapped to `"*"` or a value count, returned as `facets` (`name` and `values` of `value` and `count`, highest count first) and rendered as a `**Facet:**` list. Counts cover every record `totalResults` counts, a count above 1000 is applied as 1000, and `notice` names each facet whose values reached its limit. `rows` accepts `0` — no works and no `nextCursor`, so `{"facets": {"published": "*"}, "rows": 0}` is a pure breakdown. A facet value is escaped at line start in `content[]`, so a bracketed label such as `[unlisted]` keeps its list item, and a facets block that is not a JSON object fails as `malformed_response` (#106).
- **`clinicalTrialNumbers` and `assertions`** on `crossref_get_work` — the trial registrations a work names (`number`, `registry`, `type`; `registry` is the registry DOI where deposited) and the Crossmark entries its publisher attaches (`name`, `value`, `label`, `group`, `groupLabel`, `url`, `explanationUrl`), each returned whole in deposited order and rendered as a labelled list after **Funders:**. Both are omitted when not deposited, and a missing `clinicalTrialNumbers` does not mean the work reports no trial (#109).

## Changed

- **Per-call page caps** now size on one caller surface instead of both summed: `crossref_search_works` `rows` takes up to 500, or 1000 when `fields` names neither `abstract` nor `author`; the `crossref_search_journals` title-query list takes `rows` up to 1000; `crossref_get_references` `limit` takes up to 4000 (#107).
- **The `crossref_search_works` `offset` description** says a search with filters only and no `sort` has no fixed order, and names `sort: "created"` with `order: "asc"` for repeatable pages.
- **The clinical-trial and Crossmark projection** lives in `src/mcp-server/tools/work-assertions.ts`.

## Fixed

- **`crossref_search_funders` `worksCount`** is described and labelled (`**Registry work count:**`) as the Funder Registry record's own count, which can differ from the `funder` filter's total; a `crossref_search_works` call with `rows: 0` returns the exact figure in `totalResults`. The `replaces` description and the `crossref-guide` skill say a funder's superseded IDs fall outside both the funded-works list and the `funder` filter on its own ID, and OR'ing them into the filter counts its whole history (#108).
- **Abstract list items and empty sections** — the items of a `<jats:list>` join with `; ` where an item does not already end in punctuation, and a heading whose section holds no text (a figure-only "Graphical Abstract") is dropped, on `crossref_get_work` and `crossref_search_works` (#110).
- **An abstract that opens with a bracketed label followed by a colon** keeps it in `content[]`.
