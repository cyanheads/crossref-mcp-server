# crossref-mcp-server — Design

## MCP Surface

### Tools

| Name | Description | Key Inputs | Annotations |
|:-----|:------------|:-----------|:------------|
| `crossref_get_work` | Resolves a DOI to its full Crossref metadata record: title, authors, affiliations, abstract (when deposited), journal/container, publication date, type, license, full-text links, funder acknowledgements, and outgoing reference count. ### Input Schema Notes

- **DOI parameter:** validated with a regex pattern (`/^10\.\d{4,9}\/\S+$/`) and described as a string in the format `"10.NNNN/suffix"`. Not a branded type (schema must be JSON-Schema-serializable), but the `.describe()` gives the format with an example.
- **Filter object:** structured as `z.record(z.string())` with `.describe()` listing the valid hyphen-separated keys from the API (`has-abstract`, `has-references`, `has-full-text`, `from-pub-date`, `until-pub-date`, `type`, `funder`, `issn`, `member`, `directory`). Free `z.record(z.string())` is acceptable here because the valid set is large and the API returns an actionable validation error on unknown keys.
- **`fields` parameter (search only):** `z.array(z.string()).optional()` — narrows the fields returned by the search endpoint. Full records can be large; selecting `DOI`, `title`, `author`, `published`, `type`, `is-referenced-by-count` covers most agent workflows. Not available on `/works/{doi}` (single-fetch path). `CrossrefService.searchWorks` force-includes `DOI` in the `select=` projection whether or not the caller lists it — DOI is the work summary's only identifier and the sole key that chains into the other tools, so a projection that drops it yields unresolvable records. Crossref's select names are case-sensitive (`DOI` valid, `doi` rejected as `select-not-available`), so the dedupe matches exactly rather than case-insensitively; a miscased name still surfaces the upstream validation error naming it.
- **`offset` / `limit` parameters (`crossref_get_references`):** page the deposited reference list. Reference lists are heavy-tailed — most works deposit none at all, and among those that do a sampled median is 28 references — but bibliography records reach far higher: `10.1016/b978-0-12-397189-0.00123-3` carries 25,814, a 5 MB `structuredContent` payload if returned whole. Paging bounds both result paths identically rather than bounding only the rendered one.
- **`offset` / `limit` parameters (`crossref_get_work`) and `authorLimit` (`crossref_search_works`):** bound the deposited author list, the one array on a work record with a thousands-scale tail. Author counts are heavy-tailed the way reference lists are: across a 1,000-record sample of recent journal articles the median work deposits 4 authors, p95 is 12 and p99 is 17, while a large-collaboration paper runs past 2,900 — `10.1016/j.physletb.2012.08.020` carries 2,932, and an ordinary twenty-row subject search on supersymmetry returns over 16,000 author entries across its page. Nothing upstream can cut them: `select=` admits or omits whole top-level fields and never slices within an array, and it is rejected on `/works/{doi}` besides, so the bound has to be applied here. The default of 25 sits above p99.5 (22), so ordinary records — moderate multi-site collaborations included — come back whole. `crossref_get_work` resolves one DOI and so pages its authors properly (`offset`/`limit`, `nextOffset`); `crossref_search_works` returns many works per page, so it caps per work instead and the full list for any cut work stays reachable through `crossref_get_work`. The scope is `author` alone — `funder` peaked at 71 on a sampled record, `link` at 4, and `subject` is empty on nearly every `/works/{doi}` response, none of them within an order of magnitude of the author tail. `affiliation` is nested under `author`, so bounding the author array bounds it as a side effect.
- **`cursor` parameter (search only):** `z.string().optional()` — pass `"*"` to start cursor-based deep paging (required past ~10K results); pass the `nextCursor` token from each response to continue, until a response omits it. `/works` keeps minting a `next-cursor` past the end of a list — and hands back the very token that produced the empty page, so an unguarded walk re-sends it forever — so `nextCursor` is withheld once a page comes back empty rather than relayed. That page also carries a `notice` stating the walk is complete: the tool's whole payload is `works`, so an empty page nothing is said about renders as blank text for a client reading `content[]`. Cannot be combined with `offset`. A blank `cursor` is read as absent, as `works_cursor` is on the two sub-resource lists: form-based clients send `""` for an optional field nobody filled in, and the service picks its selector by truthiness, so a blank never reaches Crossref and the page arrives through the offset path. Normalizing at the top of the handler is what keeps the guards below reading the value the request will actually carry — otherwise the conflict guard refuses an `offset` that has no cursor to conflict with, and the empty-page notice calls an offset page a completed walk.
- **`offset` / `works_offset` parameters (`crossref_search_journals`, `crossref_search_funders`):** each tool returns two independent lists — the name-search matches and, under `include_works`, the matched record's works — so each gets its own offset input and its own `nextOffset` / `nextWorksOffset` continuation. Crossref's ceiling is not uniform across the two: `/journals` and `/funders` name search accept `offset + rows` up to 100,000, while `/journals/{issn}/works` and `/funders/{id}/works` cap ten times lower at 10,000. Both ceilings are enforced in the handler ahead of the upstream call (`offset_too_large`, `works_offset_too_large`), and a continuation offset is withheld when the following page would breach the ceiling rather than handed out for Crossref to reject — paired with a `notice` on that page, because a withheld offset and an exhausted list otherwise look identical.
- **`works_cursor` parameter (`crossref_search_journals`, `crossref_search_funders`):** the works sub-resources also accept `cursor`, which has no ceiling, so `works_cursor="*"` starts a walk of the whole works list and the `nextWorksCursor` enrichment carries the token for the page after. It is the deep-paging path for both tools: the alternative — `crossref_search_works` with an `issn:` / `funder:` filter — costs a tool switch mid-pagination and, on funders, silently changes the result set, since `/funders/{id}/works` rolls in the funder's registry descendants and the `funder:` filter does not. Cursor and offset are alternatives, not a pair: Crossref rejects the combination with `cursor-with-offset-or-sample`, and the handler refuses it first as `works_cursor_offset_conflict`. That guard keys on whether an offset would actually be spent (`works_offset > 0`) rather than on whether the field arrived, because `works_offset` carries a schema default of 0 that is indistinguishable from an omitted field — and 0 is the start of the list, never transmitted, so pairing it with a cursor discards nothing. A cursor walk cannot resume from an offset; it always restarts at the newest work, which the ceiling `notice` states outright and the `works_offset_too_large` recovery carries as "restart". A blank `works_cursor` is read as absent rather than as a cursor: form-based clients send `""` for an optional field nobody filled in, and taking that as a cursor selects the cursor path with nothing to send — the request then carries neither selector, Crossref answers page one with no `next-cursor`, and the response withholds the continuation offset too, so a 446,507-work list reads as exhausted after three records. The token itself is ~1500 characters and rides both result surfaces on every page. Crossref sets that and it cannot be shortened, but it is a fixed cost per page rather than per record, so the `works_cursor` description says to raise `rows` on a long walk instead of leaving the arithmetic to the caller.
- **`funder_doi` parameter (`crossref_search_funders`):** accepts the bare Funder Registry ID (`100000001`), the full DOI (`10.13039/100000001`), or the full DOI behind a `doi:` / `https://doi.org/` prefix. `GET /funders/{id}` resolves all three, so the validator admits every form Crossref does; the prefixes are stripped before the request. `doi:100000001` and other prefix-without-stem shapes stay rejected — the prefixes only ever precede the `10.13039/` stem.

### Error Contracts

Declared `errors: [...]` contract entries, one row per reason a handler can throw via `ctx.fail`:

| Tool | Reason | Code | When | Retryable |
|:-----|:-------|:-----|:-----|:----------|
| `crossref_get_work` | `doi_not_found` | `NotFound` | Valid DOI format but no Crossref record | No — verify DOI or try a search |
| `crossref_get_references` | `doi_not_found` | `NotFound` | Valid DOI format but no Crossref record | No — verify DOI or try a search |
| `crossref_search_works` | `cursor_offset_conflict` | `ValidationError` | Both `cursor` and `offset` supplied | No — use one or the other |
| `crossref_search_works` | `offset_too_large` | `ValidationError` | `offset + rows > ~10K` without cursor | No — switch to `cursor=*` for deep paging |
| `crossref_search_journals` | `issn_not_found` | `NotFound` | ISSN lookup returned 404 — not registered in Crossref | No — verify the ISSN or search by title |
| `crossref_search_journals` | `ambiguous_journal` | `ValidationError` | `include_works` with a title query matching more than one journal | No — re-run with one of the ISSNs the error names |
| `crossref_search_journals` | `offset_too_large` | `ValidationError` | `offset + rows > 100000` on journal title search | No — narrow the title query |
| `crossref_search_journals` | `works_offset_too_large` | `ValidationError` | `works_offset + rows > 10000` on the journal works list | No — restart the works list with `works_cursor="*"` |

| `crossref_search_funders` | `offset_too_large` | `ValidationError` | `offset + rows > 100000` on funder name search | No — narrow the name query |

Four more reasons are declared on **every** tool, spread from `UPSTREAM_ERROR_CONTRACT` in `src/services/crossref/upstream-errors.ts`. Each tool reaches Crossref through the one shared service, so each can raise all four; a contract listing only a tool's own input-shape failures under-reports what a caller has to handle.

| Reason | Code | When | Retryable |
|:-------|:-----|:-----|:----------|
| `rate_limited` | `RateLimited` (`-32003`) | HTTP 429 the retry budget could not clear | Yes — after the wait the hint quotes from `Retry-After` |
| `upstream_unavailable` | `ServiceUnavailable` (`-32000`) | Network failure, 5xx, an HTML error page served as JSON, or an empty 200 body | Yes — retried with backoff before it surfaces |
| `malformed_response` | `SerializationError` (`-32070`) | HTTP 200 with a non-empty body that is not valid JSON | No — `retryable: false`, fails on the first attempt |
| `request_timeout` | `Timeout` (`-32004`) | No response within `CROSSREF_TIMEOUT_MS`, or a 408/504 | Split — a 408/504 is retried with backoff; a deadline expiry fails on the first attempt |

Every one of them carries `data.recovery.hint`, which the framework mirrors into `content[]` as a `Recovery:` line. That is the only route by which a content-only client learns what to do next — `error.data` reaches `structuredContent` alone, so a 429 whose wait is recorded only in `data.retryAfter` is invisible to half the client population. The rate-limit hint therefore quotes the raw `Retry-After` value in its text.

Two edges the `Retryable` column smooths over. A 429 asking for a wait longer than `withRetry`'s `maxDelayMs` is surfaced immediately rather than burning attempts on a window that cannot open in time, so it can arrive having spent one attempt, not four. And a 429 that names no `Retry-After` at all falls back to the contract's own `recovery` text, which is written for exactly that case — it quotes no interval and points at no `retryAfter` field, because on this path neither exists.

`request_timeout` covers two failures whose retry economics differ, and the split lives at the throw site rather than on the contract entry. A 408 or 504 arrives as fast as Crossref answers, so an attempt costs what any other transient status costs and the entry stays retryable. A deadline expiry costs a full `CROSSREF_TIMEOUT_MS` per attempt because this server's own clock sets it, so that throw site passes `retryable: false` and the call fails on its first attempt.

Two failure classes sit outside the contract:

- **Schema rejection.** A malformed `doi`, `prefix`, or `member_id` fails its Zod validator before the handler runs and surfaces as JSON-RPC `InvalidParams` (`-32602`), not a contract reason. The validator's `message` carries the format and an example.
- **Crossref rejecting the request.** A 400 (`filter-not-available`, `select-not-available`, `integer-not-valid`) surfaces as `ValidationError` (`-32007`) carrying Crossref's own message, with the hyphenated spelling of the offending filter key when the body names one. It is the caller's to fix, so it is never retried and never re-labelled as an upstream reason.

An empty result is not an error. `crossref_get_references` returns a success with an empty `references` array and a `notice` enrichment in two cases — the work has no indexed reference list, and the requested `offset` is past the end of the list — with a distinct notice for each so a caller reading only `content[]` can tell them apart. The search tools carry the same two-notice split: an `offset` past the end of a match list (but within the route's ceiling) is a well-formed empty page with the total still reported, and its notice names the offset and the total rather than repeating the no-match text — a caller told "nothing matched" when 223 records did would go rewrite a query that was fine.

**Ambiguity is refused, never guessed.** `include_works` on either search tool resolves exactly one record. When a name query matches several, the tool throws (`ambiguous_journal` / `ambiguous_funder`) rather than reaching for a match — an embedded works list carries no identifier of its own, so a silently-chosen source is indistinguishable from the right one at the client. The test is the upstream `total-results`, not the length of the returned page: `rows: 1`, or an `offset` landing on the tail of a list, yields a one-record page that identifies nothing the caller chose, and guarding on page length would let exactly the silent pick back in through that door.

The refusal is only useful if recovery is reachable from what the client already has, so each candidate's stable identifier is written into the error *message text* as well as into `candidates` on `error.data` — content-only clients see `Error: <message>` and nothing else, so an identifier that lives only in structured data leaves them needing an undocumented exploratory call. Those candidates are one page of the matches, so the message states the full match count separately (`matchedTotal` on `error.data`) and, when the page is partial, says so and points at narrowing the query. Reporting the page length as the match count would understate the choice and hide that the wanted record may not be listed at all.

**A skipped lookup says it was skipped.** `include_works` on `crossref_search_journals` addresses the works list by ISSN and by nothing else, so a matched journal with no registered ISSN — real, and reachable by title query — has no works list to request. Returning the journal record alone is indistinguishable from a journal with no works, so that path emits a `notice` naming the cause and stating that no lookup ran. It names no retry identifier because there is none; it points at `crossref_search_works` with `queryContainerTitle` instead. The analogous branch in `crossref_search_funders` (a matched funder with no `id`) stays silent: the registry ID is the Funder Registry's primary key and is present on every record either route returns, so the branch is unreachable and a notice there would describe a state that does not occur.

**A superseded funder is reported, never followed.** The Funder Registry deprecates entries: the old record carries `replaced-by` with the current registry ID, the current one carries `replaces`. Both fields are present on every funder record, on the single lookup and the name search alike, as arrays that are empty when the relationship does not apply — so they are projected only when non-empty rather than emitted as a meaningless `replacedBy: []` on every ordinary funder. A deprecated entry answers to the same name and abbreviation as its successor while holding only the works registered against the old ID, so resolving to one returns an undercount as the answer; the response carries a `notice` naming the successor, and `format()` renders the relationship, so the fact reaches a content-only client. Auto-following the replacement would resolve to a funder the caller did not ask for, which is worse than the undercount — the caller is told and decides.

### Upstream sparsity

Normalization decides what a projected value looks like. This decides whether there is one at all.

Crossref's message schema guarantees almost nothing. A field is absent because a publisher did not deposit it, or present holding `null` because Crossref knows the fact is unknown, or present in a shape the record's other copies do not use. So a projection cannot read a field because a sample always carried it — **the line is what Crossref's deposit model permits, not what a draw happened to show**, and absence from a draw is never evidence a field is guaranteed.

**Where a shape the model permits is handled, and where one it does not is left to fail.** Two categories, and the difference is whose fault the shape is:

- **The model permits it.** A funder or an affiliation asserted through the ROR registry instead of by name; a date component Crossref records as unknown. These are ordinary deposits, so the projection handles them as the normal case — never as an error, and never with a guard that silently drops the entry.
- **The model does not.** A `null` inside a string array, a license entry with no `URL`, a member coverage fraction that is not a number. Those would be upstream corruption rather than sparsity, and each is left to fail where it is read: a value projected byte-exact reaches the output schema, which rejects it as a typed `ValidationError` naming the field, and one that passes through a normalization pass first fails there, as an internal error naming the expression that read it. No guard is written for either, because a guard would turn a corrupt upstream response into a plausible-looking result.

The record's own identity is the third case and is deliberately unguarded: `crossref_get_work` projects `raw.DOI` straight through, because a `/works/{doi}` response without one is not a record, and a fallback there would hand back a result nothing downstream could resolve.

**An organization Crossref names by identifier.** `funder[]` and `author[].affiliation[]` are the two organizations a work record carries, and a publisher may assert either through the ROR registry rather than by spelling out a name — the entry then carries `id: [{ id: "https://ror.org/…", id-type: "ROR" }]` and no `name` at all. Sampled live, 3.5% of funding assertions (143 of 4,060) and 2.6% of affiliations (349 of 13,243) arrive that way. Dropping `name` from the projection is only half the fix: an assertion reduced to an award number, or an affiliation reduced to nothing, identifies no organization, so the ROR is projected as `ror` and stands in for the name on both surfaces — it leads the `format()` line where a name would, with any other identifier trailing it exactly as identifiers trail a name.

ROR is the identifier read because it is the one every nameless entry in those draws carried, and the only one ever observed alone; an ISNI appears beside a ROR (17 affiliations) and never in place of one. The `id` array also restates a matched funder's Funder Registry DOI under `id-type: DOI`, which `doi` already carries, so the type is what selects rather than position. The residual: an entry carrying neither a name nor a ROR projects empty and renders as `(no name deposited)`. A publisher does deposit one — `10.48130/scm-0026-0005` carries an affiliation that is an empty object, one of 22,763 in a draw — which is why the render says which of the two organizations it is looking at rather than showing a blank.

**A date component Crossref does not know.** Crossref writes an unknown component as `null` inside the `date-parts` tuple rather than shortening the tuple, so a work with no registered year deposits `"issued": {"date-parts": [[null]]}` — 8% of a random works draw carries one somewhere in `issued`. Absent and null are the same fact for a caller, and every output schema declares each component a number, so `parseDateParts` omits an unknown component instead of relaying it. The read stops at the first one rather than skipping past it, because the tuple is positional and the parts below an unknown carry no meaning on their own: `[[2020, null, 15]]` is a year and a day of a month nobody named, which `formatDateParts` would otherwise render as the date `2020-15`.

**Which of the four sources answers.** A record carries its publication date in up to four fields, read in one order: `published`, which Crossref documents no definition for but which tracks the earliest of the two publication events; then each event on its own; then `issued`, which Crossref does define as the earliest of `published-print` and `published-online`. `issued` is `crossref_get_work`'s last resort and no other tool's — the three search surfaces stop after the `published-*` three — so it is the only tool the null reaches today.

The chain **advances on nothing, never on less**. A source deposited holding only unknown components states no date, which is the same fact an absent field states, so it must not silence a later source that names one. Choosing the source *object* first and parsing once does exactly that: it reads presence as an answer and hands back no publication date for a record that carries one two fields along. In the other direction the chain stops at the first date rather than continuing for a more precise one, because the four sources answer different questions rather than one question at four precisions — a coarse `published` beside a precise `published-online` is not a partial answer to be completed, and refining across the two would report the online date as the work's publication date. 580 of 6,000 randomly drawn works carry a `published` coarser than a later source in the chain, against 5,394 of 5,428 whose `published` is exactly the earliest of the two events.

That order is one order because it lives in one place. `resolveWorkDate` and `resolveWorkSummaryDate` take the record rather than a chain of its date fields, so a call site has nothing to chain — the two spellings that disagreed, source-first at `crossref_get_work` and result-first on the three search surfaces, are not expressible at one. What keeps the next caller on the same rule is a test rather than a type: every tool whose output declares a publication date is driven over a record shaped for the divergence, on both result surfaces, and a definition that declares one and is driven by nothing fails there.

Sampled live, no record reaches the disagreement: across 73,398 works — 6,000 random draws, a cursor walk of the index, and walks of the work types whose date metadata is thinnest — every null component sat in `issued` and none in `published`, `published-print`, or `published-online`. Which field is required is why: `issued` is the one of the four the API guarantees, so a record with no publication date at all carries the `[[null]]` placeholder there while the other three are omitted outright — and `issued` is last in the only chain that reads it, with nothing behind it to disagree with. That is a fact about the deposits drawn, not about the model: `date-parts` admits a `null` in any of the four, so absence from a draw settles nothing about whether the shape can occur.

**The types are the enforcement.** `CrossrefFunder.name` and the affiliation element's `name` were both declared required in `src/services/crossref/types.ts`, and `date-parts` was declared `Array<Array<number>>`. A projection is only as total as its input type claims, so the compiler reported all three as exhaustive while they were not, and a `TypeError` at the first `normalizeText` call was the first anyone heard of it. The declarations now say what Crossref actually guarantees, which is what makes the compiler — rather than a live record — point at the next site.

### Text normalization

Every human-readable value projected out of a Crossref record passes through one baseline: character references decoded, whitespace collapsed to single spaces, trimmed (`normalizeText`). Identifiers and machine-format values — DOIs, URIs, ISSNs, prefixes, dates, work types, coverage categories — are returned byte-exact and never go through it.

**What the decode resolves.** The full HTML5 named character reference set — 2,125 semicolon-terminated names, taken verbatim from the WHATWG's own data file — plus decimal and hex numeric references. Sizing the gap a shorter table leaves: across 11,900 sampled works and 350,212 free-text fields, 1,090 fields carry a named reference and 2,982 references appear under 49 distinct names. The five XML names (`amp`, `lt`, `gt`, `quot`, `apos`) account for 94.9% of the occurrences but 5 of the 49 names; the other 44 are 152 occurrences spread almost evenly — `ndash` (25), `ldquo`/`rdquo` (22 each), then a flat tail of Greek letters, accented Latin, guillemets, and typographic marks appearing once or twice each. That distribution is what rules out a hand-picked table: nothing converges, so any sample-sized list is the next sample's bug. The spec's set is closed and stable, and it is what the deposits draw from, so it is the whole table.

Three boundaries the table does not cross, each of which has a deposit behind it:

- **A reference must terminate in a semicolon.** The legacy no-semicolon forms HTML still parses (`&copy`, `&times`, `&not`) are out. In deposited citation text an unterminated `&` is almost always an ampersand somebody typed — `Nuc. Sci. &Eng 2013` is a journal abbreviation, `R&D` and a URL's `?a=1&lang=en` are not references — so requiring the semicolon is what keeps a bare `&` bare.
- **Names are exact.** `&AMP;` is defined and decodes; `&Amp;` is not and stays as deposited, as does `&Eng;`. Both were observed in the sample.
- **A numeric reference that names no scalar value is left as source text.** Zero, past the last code point, or half of a surrogate pair — the deposited text is the more useful answer, and a lone surrogate on the wire is a serialization hazard.

The decode is a **single pass** over the string, which is what keeps a reference from being resolved twice. `&amp;lt;` is the escaped text `&lt;` and decodes to exactly that. A chain of per-name replaces — the shape the five-name table had — decodes it twice and yields `<`, manufacturing markup out of text a publisher escaped precisely so it would not be markup.

The decode also runs **before** the whitespace collapse, so a reference naming a whitespace character folds into the surrounding run rather than reaching `content[]` intact: `&#10;` does not become a line break that splits the Markdown around it, and `&nbsp;` does not become a space a reader cannot select or search for.

Two families of field carry markup, and they get the same rule over one implementation (`stripMarkup`). The **JATS-deposited fields** — work `title`, `subtitle`/`short-title`, `container-title`, `abstract` — reach it through `normalizeMarkupText`; **reference free text** — `unstructured`, `article-title`, `journal-title`, `author` — through `normalizeReferenceText`. Order is load-bearing on both: tags come out before entities are decoded, so a deposited `&lt;i&gt;` survives as literal text instead of decoding into a tag the strip pass would then eat. Whitespace collapse runs on *any* run of whitespace rather than runs of two or more — a lone `\n` in a deposited title splits the Markdown heading in `content[]` on its own, and the indented continuation renders as a code block.

**Where the line falls.** A bracket is removed only when it is recognizable as markup, on four tests applied in order:

1. **Shape.** The element name follows `<` with no space, and the attribute tail is `name="value"` pairs rather than prose. This is what separates `<span class="smallcaps">` from `<Stack Overflow, https://…>` and `<Available from: …>` — both of the latter parse as a tag under a looser `<name\b[^>]*>` and lose their whole span, and both are text a reader needs.
2. **Region.** A MathML formula, a JATS structured citation (`<mixed-citation>`, `<element-citation>`, `<nlm-citation>`, `<citation>`), and an `<alternatives>` wrapper are matched end to end, because inside such a region every bracket is a tag by construction — nobody types a Miller index inside `<mixed-citation>`. The first two are emptied of tags; the third holds one object encoded several ways and is reduced to one of them. Matching the region rather than enumerating its children makes the strip all-or-nothing: an unclosed region matches nothing and is left whole rather than half-consumed, and any child element the vocabulary defines is handled whether or not it has been seen before.
3. **Name.** Everywhere else the element name decides, on the three separator classes below plus a per-surface default. A name is admitted on two tests: **nothing of the element's value lives in an attribute**, and **the name is a markup-only token rather than an ordinary word**.
4. **Address.** A link element — `a`, `ext-link`, `uri` — is the one class a name cannot settle, because whether anything of its value lives in an attribute is a property of the occurrence and not of the name. Its tags come out only where removing them cannot cost the reader the address, on the rule below.

**The one difference between the two surfaces is what an unrecognized element name means**, and it follows from what kind of string each field is. A title or abstract is deposited as JATS, so a raw `<` in it came out of an XML document: an unrecognized name is structure — `<sec>`, `<title>`, `<list-item>`, `<boxed-text>` — and is removed as a block boundary. A reference entry is a citation string a publisher typed, and the same syntax carries content: an unrecognized name is presumed content and stays. Every other behavior is shared, which is what keeps the two from drifting apart; the classification table both passes read is exported so a test can drive the caller-visible outcome of every name in it.

The admission tests are what keep names off the separator classes, and each exclusion follows from one of them. **Link elements** — `a`, `ext-link`, `uri` — fail the first: the address can sit in an `href`, where a removed tag deletes it. They are the one exclusion the name cannot settle on its own, so test 4 takes them. **Bare ordinary words** — `volume`, `year`, `source`, `comment`, `ref`, and the rest of the single-word JATS citation vocabulary — fail the second: a bracketed ordinary word is how a person writes a quotation or a note, so admitting one would delete reader content. `<ref>` is the demonstration — its one occurrence in the reference sample is a paper title about Wikipedia's `<ref>` tag, not a tag. Those names still come out inside a citation envelope, where test 2 has already settled that nothing was typed by hand.

**A link element is settled per occurrence, because the premise for keeping it has to be checked rather than assumed.** The premise is that the address lives in an `href` where removing the tag deletes it. Often it does not: a structured abstract deposits a URL, an accession, or a trial registration as the element's own *text* and repeats it in the `href`, and there the tag protects nothing while putting a namespace-bearing XML tag in the middle of an abstract. So the tags come out on three findings, and stay otherwise:

- **No attribute.** Nothing of the element's value lives in one, so nothing can be lost — a `<uri>` deposited around a bare URL, an `<a>` carrying only a `name`.
- **Nothing outside the deposit is addressed.** An empty `href`, or a bare fragment (`#b1`, `#nph15488-sec-0002`), names a place inside the publisher's own XML. A reader does not have that document, so the fragment resolves to nothing and preserves nothing.
- **The text already carries the address**, verbatim or less its scheme.

**The scheme is the only difference that comparison forgives, and the line is where it is on purpose.** Losing `http://` in front of `www.fasebj.org` costs a reader nothing they cannot supply; losing the `/ct2/show/NCT02196038` behind `https://clinicaltrials.gov/` costs them the thing being addressed, which is the failure the whole rule exists to prevent. A scheme says how to fetch; everything after it is what gets fetched. Both neighbouring rules are worse. Requiring **equality** rather than containment keeps the tag wherever the deposit wraps a sentence around the URL, protecting nothing. Forgiving **more** — treating `www.` as optional, ignoring a trailing slash, decoding percent-escapes, resolving a DOI through `doi.org` — each asserts that two different strings name the same resource: `www.x.org` and `x.org` are different DNS labels, `%2F` and `/` are different path bytes, and a resolver-host rule answers only for the hosts someone remembered to list. Every one of those assertions is a way for the identifying part of an address to go missing.

The rule holds on both surfaces and inside a structured-citation envelope, where every other name comes out unconditionally: an envelope settles that nothing inside it was typed by hand, which says nothing about where an address lives. A MathML region is the one place it does not hold — inside a formula every tag comes out, and nothing there carries an address. A link that comes out leaves an inline word boundary, like the emphasis around it. A link that stays keeps its tag exactly as deposited, and reaches a Markdown reader intact — see **Reaching a Markdown reader** below, which is one rule over every bracket that survives deliberately rather than a treatment for links alone.

Three separator classes, by what the element means for the text around it. **Scripts and inline formula wrappers** (`sub`, `sup`, the `inf` spelling Elsevier and IEEE deposit, the `subscript`/`superscript`/`stack` spellings Springer deposits, and the `formula`/`inline-formula`/`ref_formula`/`tex`/`tex-math` wrappers) leave no separator, because their content continues the token around them: `O<sub>2</sub>` is one formula, `T<inf>c</inf>` is one symbol, and `<tex Notation="TeX">$\hbox{1}/f$</tex>` reads as the TeX it wraps rather than as TeX wrapped in XML. **Inline emphasis** (`i`, `b`, `em`, `italic`, `strong`, `small`, `bold`, `scp`, `sc`, `u`, `span`) and the bare JATS citation fields (`etal`, `fname`, `article-title`, `surname`, `given-names`, `string-name`, `person-group`, `collab`) are a word boundary and leave a space **only where the text would otherwise run together**: between two word characters, or where a sentence ends and the next word begins. The first is why an italic journal title closes up — it is followed by a comma far more often than by a word, and a space for every tag puts a stray one before the comma on nearly every entry it touches. The second is why a sentence-ending `.`, `:`, `?`, or `!` counts on the left the way a word character does: a publisher who marks a structured abstract's headings with `<bold>` rather than `<title>` deposits `…effectiveness of MOC.<bold>Methods</bold>`, which is two sentences and not one word. It counts on the left only, since a following word character is what earns the space, so `Downe et al.<i>(2001)</i>` still closes up; and a comma is not on the list, because a chemical name that italicizes its locants runs straight through one (`<i>N</i>,<i>N</i>-Dimethylformamide`). **Block elements** (`p`, `br`, `disp-formula`, and the `refersplit` marker one publisher appends to each packed citation) always leave a space, because a publisher packing several citations into one field separates them there and the text before the boundary ends in a period, not a word character.

**An `<alternatives>` wrapper is the one region that selects rather than strips.** It holds several encodings of one object and expects a consumer to pick one: a formula's TeX beside the same formula's presentation MathML, or a graphic beside the TeX that reproduces it. Emitting every child that carries text renders one expression twice — the defect `<annotation>` had, in a construct the annotation rule does not reach, because `<annotation>` is a labelled second copy *inside* a MathML region while these are siblings with no marked primary. What is kept is the **first child carrying any text at all**, returned as deposited so the passes after it classify it like any other markup. Position rather than notation is what decides: ranking TeX above presentation MathML or the reverse would be this server ranking notations it has no standing to rank, and would need extending each time the vocabulary admits another encoding, while a positional rule passes over a text-free `<inline-graphic>` on that basis and covers a child element nobody has seen. A wrapper holding no child element at all keeps its content, since nothing in it can be a duplicate. `alternatives` is an ordinary English word, and matching the closed pair is what keeps it off the reference surface's content: a reader who brackets the word does not also close the tag, and an unclosed wrapper falls to the name rule like any other bracket.

**The boundary a wrapper leaves is the wrapper's own, not the selected child's**, and it is the block boundary a MathML region gets, for the same reason: what it holds is a formula, and a formula stands as its own token in the sentence rather than continuing the word beside it. It has to belong to the wrapper because publishers deposit the encodings in either order — decided by the child, the same construct would separate where the MathML came first and close up where the TeX did, and `on a time scale<inline-formula>…` would read `on a time scale$\mathbb{T}$with`. Across 10,000 sampled works and 328,920 projected values the boundary changes 7, every one of them a field carrying a wrapper: three gain a separator the prose needed (`Reynolds number $Re = 2000$ is`), and four gain a space before a comma, a period, or a hyphen. That second outcome is the trade a formula boundary already makes on this surface — a MathML region in the same position renders `P<0.01 ), but there was no association` and `the target space is on S2 . This solution` today — so it is the class behaving consistently rather than a new cost, and the alternative is a fourth separator class that only one construct would use and that would space a wrapped formula differently from a bare one.

A MathML region is the one construct whose inside and outside disagree, and deliberately: its inner tags join tight so the expression reads as one token (`<msub><mi>Airy</mi><mn>2</mn></msub>` is `Airy2`), and its outer edge is a block boundary because the formula stands as its own token in the sentence rather than continuing the word beside it. A MathML deposit carries the whole symbol — `<mmultiscripts><mi>Si</mi>…<mn>33</mn>` is all of `³³Si` — and publishers deposit it hard against the prose, so a tight outer join reads `thin films ofSi33and partially filled`. The pretty-printing whitespace between a region's tags comes out with them, since it is insignificant in XML; a formula needing a visible space writes it as a character reference, which the strip does not touch and the decode resolves afterwards. A MathML deposit also carries its expression a second time as a TeX or Content-MathML `<annotation>`; that payload is dropped with the region's tags, or the same formula renders twice.

Every separator is decided against the string the tags sit in, and a tag never counts as a word character, so removing one class can never create an adjacency another class then misreads. `<span class="smallcaps">xvii</span><sup>e</sup>` is a French ordinal: read `</span>` against a neighbouring `<sup>` rather than against the letter behind it and the word-boundary rule splits one word into two.

**Opening and closing tags are not symmetric, and that is what keeps an element from coming apart.** An opening tag is removed on its own evidence; a closing tag is removed only if the matching opener was. A valueless attribute (`<span hidden>`, `<i lang>`) fails the shape test — it is prose as far as that test can tell, and admitting one reopens `<Bold statement about X>`, which parses as three of them — while the attribute-free `</span>` matches the shape on its own. Left to itself the element half-strips: opener kept, closer removed. A lone closer has no claim to being a tag beyond an opener the pass already declined to treat as one, so it stays.

**Reaching a Markdown reader.** Everything above decides what a value *is*; one more rule decides how it is *shown*. `structuredContent` carries that value as normalization produced it, and `content[]` carries a Markdown rendering of the same value — so every bracket the rule above keeps is read a second time, this time by the client's renderer. A renderer consumes an unknown element as its children alone, so a kept `<ext-link xlink:href="…">WHO</ext-link>` shows `WHO` and the address is gone; it resolves a character reference, so the `&lt;` a publisher escaped twice becomes `<`; it reads `<http://faostat.fao.org/…>` as an autolink and eats the brackets somebody typed; and it takes a deposited `*` for the closing half of the `*…*` that `format()` writes around a journal title. What the strip protected, the render then deleted — and it landed hardest on the kept link, the case the keep exists for.

So every value the normalization passes produced is escaped on its way into a Markdown line, once, in `format()`. That is the seam because it is where the two surfaces part: normalization owns what the value contains and `structuredContent` is a contract over exactly that, so a backslash written into the value would change the machine-readable surface to fix a rendering defect. Written at the render boundary it reaches only the surface that needs it, and the two then agree on every character. The rule is one shared function (`mdText`, with a second entry point for a value that begins its line) rather than seven renderings of the same idea, and a test drives all seven tools over one probe so a field rendered without it fails there rather than in a client.

A character is escaped only where a reader would take it for markup, which is what keeps the escape off ordinary prose:

| Escaped | Left alone |
|:--|:--|
| `<` before a name, `/`, `!`, or `?` — raw HTML or an autolink | `<` anywhere else: `0.01 < x > 0.8`, `Silicon <100> nanowires`, `66:2<131::AID-QUA4>` |
| `&` heading a well-formed character reference, mirroring the decode | a bare ampersand somebody typed: `R&D`, `Taylor & Francis`, `?a=1&lang=en` |
| `` ` ``, `*`, `~` — the markers `format()` writes into its own lines | `_`, which this server never writes |
| `]` before `(` or `[`, which would complete a link | `[` on its own: `[18F]FDG`, `[Ca2+]`, `[1,2]` |
| `\` before the punctuation it can escape — a TeX `\%` keeps its backslash | `\` before anything else: `\bot`, `\hbox` |

The conditions are what the measurement bought. Across 12,000 sampled works, 6,565 reference fields carry an ampersand and 60 carry a character reference; 2,504 carry a `[` and 8 carry the `](` that would make one a link. Escaping either character unconditionally would mark up two orders of magnitude more text than it protects. `_` is left alone on the same arithmetic from the other direction: 76 of 215,933 values carry an underscore that could flank at all and 45 carry the two a pair needs, what a pair costs is the two markers rather than the text between them, and escaping it would blind the format-parity linter — which probes with an underscore-delimited sentinel and guards the same two-surface invariant across every tool.

**A block construct is the one class the placement decides rather than the value**, so it is escaped at the call site that can open one instead of in the shared rule. A value that begins a line with `#`, `>`, `-`, `+`, or a number and a dot is read as a heading, a quote, or a list item, and the renderer eats the marker that opened it: an abstract opening `19. yüzyılın` loses the `19.` that names the century, one opening `- ` loses the hyphen and space a publisher deposited, and a value that is nothing but `-` or `=` is consumed whole and turns the label above it into a heading. Anywhere else on the surface those characters are inert, because every other rendered value sits behind a `## `, a `- `, or a `**Label:** ` — 1,201 of 328,920 sampled values open on one, and escaping them all would put a backslash in front of the leading hyphen of every title that starts with one. So `mdText` has a second entry point, `mdTextAtLineStart`, and exactly one line calls it: the abstract `crossref_get_work` renders at column zero. It escapes the last character of the marker — the `.` of an ordered-list marker rather than the digits, since `\1` is not an escape a reader resolves — and it tests the construct rather than the character, so `2.25Cr1Mo0.25V`, `1.8-MeV`, and `-- no abstract provided by author --` are left alone: a list marker is followed by a space or by nothing. 14 of 6,967 sampled abstracts are escaped by it. Which call sites need it is enforced the same way the inline escape is: the cross-tool probe opens on a block marker, and a rendered line that begins with the inline-only form of the probe fails it, whichever tool grows that line.

Two things the escape does not cover. Each is left uncovered on its own grounds, and each leaves something live rather than solved. **Machine-format values** — DOIs, URLs, ISSNs, prefixes, ORCIDs, and reference keys are projected byte-exact and rendered the same way, because they are what a reader copies and a backslash inside a URL breaks the copy and the autolink both; 0.41% of them carry a Markdown-active sequence, almost all of it one publisher's XPath-shaped reference keys. A URL a publisher typed into a *citation string* is prose rather than one of those fields, so it is escaped with the prose around it — a `~` in a path reaches `content[]` as `\~`, which a renderer resolves and which is the trade that keeps a second `~` in the same string from striking the address through. **Enrichment and notice text** — a notice is one string the framework merges into `structuredContent` and renders into `content[]`, so escaping it would put the backslash on the structured surface. Two notices quote a deposited value: the one `crossref_search_journals` writes when `include_works` is asked of a journal with no ISSN, and the deprecation notice `crossref_search_funders` writes over a replaced funder. Both quote a name the strip has cleared of *markup*, which is not the same as cleared of metacharacters, so a name carrying one reaches `content[]` live.

Measured after: of 459,382 values projected out of 12,000 works, the escape changes 573 (0.125%) — 215 carrying a tag-shaped bracket, 137 an asterisk, 103 a character reference, 77 a tilde, 26 a backtick, 20 a link-shaped `](`, 7 a live backslash. No value loses a character, and nothing in the escape set survives unescaped; the two residuals above are what sits outside that set.

**Sizing, and what the samples do and do not establish.** Reference free text, across 49,700 works — 754,865 reference entries, 1,336,135 free-text fields — carried an angle-bracket span in 3,063 fields (0.23%), split between real markup and text a strip would delete: a bracketed URL (`<http://faostat.fao.org/…>`, `<www.ecfr.gov>`), a Miller index (`Silicon <100> nanowires`), a DOI fragment (`<131::AID-QUA4>`), an acronym (`<IR>`), an inequality written `0.01 < x > 0.8`, a guillemet quotation (`entre <<ruptures>> affichées`), and a bracketed note whose first word happens to be an element name. A blanket `<[^>]+>` strip deletes every one of them; the rule above cleans 2,467 of the 3,063 and deletes none. The JATS surface is a different distribution: across an independently drawn 12,000 works — 26,108 title/subtitle/short-title/container-title/abstract values, 3,193 of them bracket-carrying — **every** bracket span was a well-formed tag and none was content, which is what a field that has to be valid XML predicts. The names there are structural rather than inline: `p` (8,099 spans), `title` (3,385), `italic` (2,727), `sec` (1,898), `sub` (1,240), `sup` (1,128), and a tail of `list-item`, `label`, `caption`, `fig`, `boxed-text`, `disp-quote`, table elements, MathML, `inline-formula` (110), `tex-math` (84), and `ext-link` (25 spans across 6 fields).

Every count here sizes a decision; none bounds the corpus. Brackets cluster hard by publisher, so redraws of the same design move the overall rate by 2× and the per-class counts by 2–11×, and `refersplit` — the self-closing separator that reaches 10 fields in one 6,000-work draw — is absent from a 12,000-work draw entirely. Absence from a sample is not evidence of rarity, which is why membership rests on what an element *is* rather than on how often it was seen.

Link elements were sized on their own draws, since the question they raise is not how often a bracket appears but where the address behind it sits. A 22,000-work draw of the JATS surface — 47,764 title/subtitle/short-title/container-title/abstract values — carries a link element in 28 fields, 66 elements between them. The address is in the text verbatim in 19, in the text less its scheme in 1, a bare fragment in 13, and in no attribute at all in 2; in the remaining 31 the `href` addresses something the text does not name, so those keep their tags. A separately drawn 12,000 works on the reference side — 332,633 free-text fields, from the 5,111 of those works that deposit references — carries a link element in 21 fields, and in every one the text carries the address, 20 verbatim and 1 less its scheme. Running the rule over both draws removes 56 opening tags and loses no address at all.

Neither draw settles how the two outcomes divide, and the reference draw in particular reads far cleaner than the corpus is: the JATS side's 31 kept elements come from 8 fields and 24 of those from 3 works — a taxonomy record that hyperlinks each rank to a nomenclature registry, an article that links gene names to UniProt — so a draw that misses those publishers sees a rate near zero. What the two draws do establish is that both outcomes are real and neither is a corner case, which is why the rule checks rather than assumes in either direction.

**Three residuals, and why each is accepted.** On the reference surface a single-letter allow-list name used as literal content — `variant <b> allele`, a physics expectation value written `<p>` — is removed. The shape test closes the multi-word form (`<B. subtilis>`, `<Bold statement about X>` survive), so only the bare `<b>`/`<i>`/`<p>` form is exposed, and no sampled field contains one. On the JATS surface the block default removes a bracketed single token that reads as an element name — an acronym, a bare domain, an ordinary word — because it cannot be told from `<sec>`; the alternative leaves structural tags standing in every structured abstract, and the 12,000-work sample contains no content bracket on that surface at all. On both surfaces, a link the rule keeps reaches the reader as a raw XML tag in the middle of prose — 8 fields in 47,764 — and now reaches a Markdown reader that way too, address included, rather than being consumed. Rewriting it to something like `text (href)` would read better and was rejected for the reason it has always been: it puts into the field a string the publisher deposited in an attribute rather than in the text. All three are pinned by tests, so a later change to any of them moves visibly rather than silently.

**Membership is deliberately narrow.** `refersplit` is the most recent addition, and it went in by name. Admitting it by *shape* instead — treating any self-closing tag as markup — was the obvious alternative and is wrong: `<www.voith.com/>` is a bare-domain URL bracket that parses the same way, and deleting it is the failure the whole rule exists to prevent. Names observed on the JATS surface but left unadmitted (`styled-content`, 354 spans; `named-content`, 30; `underline`, 18) gain nothing there — the block default already removes them — and would widen the reference allow-list against zero observed occurrences, so they stay off.

### `format()` Notes

Both surfaces (`structuredContent` from `output` and `content[]` from `format()`) must carry the same data. `format()` is not a count/title stub — it must render title, authors, DOI, abstract (or "not deposited"), reference count, license, and the reference list with resolved DOIs where available.

**Parity rule:** `format()` never truncates, caps, slices, or rounds away anything present in `output`. It renders every element of every array and the full text of every string it surfaces. Truncation applied only in `format()` produces client-specific data loss — content-only clients silently lose data that structured-content clients receive, with no retrieval path.

Rendering the full string is not the same as the reader receiving it: `content[]` is Markdown, so an interpolated value is parsed a second time by the client and a bracket or a metacharacter the deposit carried can be consumed there. Every value the normalization passes produced is therefore escaped on its way into a line — the one thing `format()` does to a value beyond placing it. See **Reaching a Markdown reader** under Text normalization for the rule and what it deliberately leaves alone.

When a payload genuinely needs bounding, bound it **symmetrically in the handler** so both paths carry the identical page, and expose the retrieval input that reaches the rest. `crossref_get_references` is the worked example: `offset`/`limit` inputs page the list, `referenceCount` reports the full deposited total, and `nextOffset` enrichment hands back the input for the following page. `crossref_search_journals` and `crossref_search_funders` follow the same shape twice over, once per list they return. Numeric rendering follows the same rule — precision scales to magnitude so a small nonzero value never renders as zero (see `formatCoverage` in `crossref_get_member`).

The author list is the same pattern applied to an array nested inside a record rather than to the record's whole payload, and it shows what the pattern turns into when the tool cannot page. `crossref_get_work` resolves one DOI, so it is the pure case: `offset`/`limit`, `authorCount`, `nextOffset` — the reference-list shape, field for field. `crossref_search_works` already spends its own paging on the works list, so a second offset over the authors of an arbitrary work on the page has nothing to page relative to; it caps per work at `authorLimit` instead, reports each work's `authorCount`, and names `crossref_get_work` as the route to the authors it left out. What both keep is the invariant `crossref_get_references` established and #32 defended: a bound is never applied silently. `authorCount` beside a shorter `authors` array is what makes a cut list visibly cut on `structuredContent`; the `format()` line that renders the same "showing N of M" alongside the retrieval call is what makes it visible on `content[]`; and the enrichment trailer carries the page-level fact to both. Removing any one of the three would restore exactly the failure #32 closed — a shortened list a caller cannot tell from a complete one.

Enrichment is a parity surface, not a structured-content-only one: the framework merges enrichment into `structuredContent` **and** renders it as a trailer block appended to `content[]`. Page metadata therefore lives in `enrichment` rather than being duplicated into `output` — one declaration, both paths. The corollary is that a field the enrichment block does not declare is stripped from `structuredContent` and omitted from the trailer, silently, no matter what the handler computed or `format()` renders. Tests assert new fields by parsing through `output.extend(enrichment)` (or by driving the definition with `runToolContract`), so deleting a *declaration* fails a test rather than quietly shrinking the wire payload.

## Overview

crossref-mcp-server wraps the Crossref REST API to expose canonical scholarly metadata for ~155 million registered works (journal articles, books, chapters, conference papers, preprints, datasets, components). It is the authoritative source for DOI-registered metadata — titles, authors, affiliations, abstracts (where deposited), licenses, full-text links, funder acknowledgements, and outgoing reference lists. It reports an incoming citation count (`is-referenced-by-count`) but not the citing works; citation graphs belong to OpenAlex.

**Pairs with:** pubmed-mcp-server (biomedical-specific abstracts/MeSH), openalex-mcp-server (analytics, citation graphs, topics, concepts), arxiv-mcp-server (preprints — their DOIs resolve through Crossref), biorxiv-mcp-server (preprints — same).

## Requirements

- Read-only. No writes to Crossref.
- All requests include a polite-pool `User-Agent` header (`crossref-mcp-server/0.1.0 (mailto:<CROSSREF_MAILTO>)`) when `CROSSREF_MAILTO` is set. The env var is optional — without it the server starts but uses the anonymous pool with stricter rate limits. No token is required — polite-pool access is granted solely via the mailto User-Agent.
- Offset paging on `/works` is capped at ~10K results per query. Results beyond that require cursor-based paging (`cursor=*` to start, then pass the `next-cursor` value from each response). Mixing `cursor` and `offset` is not supported. `/works` never terminates a walk by withholding the token, and the token itself carries no progress signal: after the first response the same 1512-character value comes back on every page of the walk, item-bearing and empty alike, so comparing one page's token to the next says nothing about where the walk is. Past the end the route answers `items: []` and hands that same token back indefinitely. The empty page is the only end-of-list signal upstream provides — verified on `/works`, `/journals/{issn}/works`, and `/funders/{id}/works`.
- The offset ceiling is per-route, not global. `/journals` and `/funders` name search accept `offset + rows` up to 100,000; `/journals/{issn}/works` and `/funders/{id}/works` cap at 10,000. Past either, Crossref answers HTTP 400 `integer-not-valid` naming the ceiling for the supplied `rows`. Both works sub-resources accept `cursor` instead, which has no ceiling; the name-search routes do not.
- Filter keys use hyphens (`has-abstract`, `has-references`, `has-full-text`, `from-pub-date`, `until-pub-date`). There is no `is_open_access` filter; use `directory:DOAJ` to restrict to DOAJ-indexed open-access content.
- The `select` field parameter works on `/works` (search) only. It is not supported on `/works/{doi}` (single record fetch).
- Outgoing reference lists are only available for works where Crossref has indexed them; coverage varies by publisher.
- Abstracts are deposited at publisher discretion; many records lack them.
- `has-full-text` filter returns works with registered full-text links — access may still require a subscription.
- Incoming citations are not exposed by Crossref. Attempts to retrieve them must be redirected to OpenAlex.

## Services

| Service | Wraps | Used By |
|:--------|:------|:---------|
| `CrossrefService` | Crossref REST API (`https://api.crossref.org/`) | All seven tools |

### CrossrefService design

- Singleton, initialized in `setup()`, accessed via `getCrossrefService()`.
- Injects polite-pool `User-Agent` on every request from config.
- Raw `fetch` for all HTTP, not the framework's `fetchWithTimeout` — the helper throws on non-2xx and hands back only a truncated body string, which would cost the 400 branch its parse of Crossref's `validation-failure` body and turn every 404 into a logged error rather than the `null` the handlers convert into a typed reason. The two mechanisms worth having from it are replicated locally instead: an `AbortController` aborted with a `TimeoutError` DOMException, matched by identity, and a `catch` around the transport that reports the network failure's `.cause`.
- Every failure leaves `attempt()` as an `McpError` with a classified code. That is what makes retry behavior correct rather than incidental: `withRetry`'s default predicate treats *any* non-`McpError` throw as transient, so an unwrapped `SyntaxError` or `TypeError` is both retried to exhaustion and then classified from its constructor name.
- `withRetry`: 3 retries on top of the first attempt, 1s base delay (rate-limit recovery), exponential backoff, upstream `Retry-After` honored over the exponential value. The stock predicate is kept — no custom `isTransient`. Two throw sites opt out with `retryable: false`. Bytes that arrive complete and then fail to parse throw `malformed_response`, because an identical GET re-serializes the same corrupt body; an HTML error page and an empty body throw `upstream_unavailable` instead, since the first is a maintenance interstitial and the second a truncated or dropped response, and both can clear on a retry. And a client-side deadline expiry throws `request_timeout` non-retryably, because it is the one transient failure whose cost is set by this server's clock rather than by how fast the upstream answers: four attempts at the default `CROSSREF_TIMEOUT_MS` is ~40s of deadline plus ~7s of backoff before the caller hears anything, which can exceed an MCP client's own request budget and leave the recovery hint unread. The same reason raised from a 408/504 keeps the full budget — those arrive at upstream speed.
- Field selection: `select=` works on `/works` (search) only — not on `/works/{doi}`. For `crossref_get_references`, fetch the full record from `/works/{doi}` and extract the `reference` field from the response body rather than using a select shortcut.
- Pagination: `offset` is honored on `/works`, on both name-search routes, and on both works sub-resources; the ceiling differs by route (`NAME_SEARCH_OFFSET_CAP` = 100,000, `WORKS_OFFSET_CAP` = 10,000, `/works` ~10K). `cursor` is accepted on `/works` and on both works sub-resources and has no ceiling: pass `cursor=*` on the first request, then the `next-cursor` token from each response. Cursor and offset cannot be used together — one `setSubResourcePage` helper writes whichever applies, cursor first, and an offset of 0 is left off the query string entirely. Throw when offset is requested past the ceiling and cursor was not supplied. `nextPageOffset()` classifies a page's continuation as `next` / `end` / `ceiling` rather than returning an offset-or-nothing: `end` and `ceiling` both withhold an offset but mean different things to a caller, and collapsing them into one absent field is what makes a truncated list read as a complete one. A cursor page has no position, so it carries neither a continuation offset nor a ceiling; its token is withheld on an empty page, since Crossref keeps minting one past the end of a list and a caller reading "absent means exhausted" on the offset path must be able to read it the same way here.
- List envelopes: `searchJournals` / `searchFunders` return `{ totalResults, items }` rather than a bare array — the `total-results` field is what tells a caller more pages exist. The ISSN and funder-DOI single-record paths report a total of 1 and ignore `offset`, since neither route pages.
- Status mapping: 429, 408/504, and 5xx map onto the upstream contract; 400 and 404 are left with the treatment the handlers depend on. The 5xx branch also lifts 500/501 out of the framework's default `InternalError`, which would report a Crossref outage as a bug in this server and would not be retried.

## Workflow Analysis

**`crossref_search_journals` with `include_works: true`** (2 upstream calls):

| # | Call | Purpose |
|:--|:-----|:--------|
| 1 | `GET /journals?query=…` or `GET /journals/{issn}` | Resolve journal, return metadata |
| 2 | `GET /journals/{issn}/works` | Fetch a page of recent works for the matched journal |

Both calls run sequentially (step 2 depends on ISSN from step 1). Step 2 is only made when `include_works: true`, and only when step 1 matched exactly one journal upstream — a title query matching several throws `ambiguous_journal` instead, however many of them fit on the requested page. Each step carries its own offset (`offset`, `works_offset`) against its own route ceiling.

**`crossref_search_funders` with `include_works: true`** (2 upstream calls):

| # | Call | Purpose |
|:--|:-----|:--------|
| 1 | `GET /funders?query=…` or `GET /funders/{id}` | Resolve funder, return metadata |
| 2 | `GET /funders/{id}/works` | Fetch a page of funded works for the matched funder |

Same sequential pattern, same guards: step 2 only on `include_works: true`, only when step 1 matched exactly one funder upstream (otherwise `ambiguous_funder`), and each step pages independently.

Note that `/funders/{id}/works` and a `filter=funder:10.13039/{id}` search on `/works` are close but not identical sets — the sub-resource rolls in the funder's registry descendants, so its `total-results` runs higher. That is why deep paging is threaded through the sub-resource as `works_cursor` rather than delegated to `crossref_search_works`: the filter would reach past the ceiling while quietly answering a narrower question.

No multi-hop reference traversal. `crossref_get_references` returns a single hop. Agents that need N-hop traversal chain the tool explicitly — this keeps individual calls bounded and lets the agent decide the depth.

## Known Limitations

- **No incoming citations.** Crossref does not expose which works cite a given DOI. For citation counts, incoming references, or citation graphs, use OpenAlex.
- **Abstract coverage is incomplete.** Abstracts are deposited voluntarily by publishers. Many records — especially older works, books, and non-OA journal content — have no abstract.
- **Reference list coverage varies.** Outgoing reference lists are only present for works whose publishers participate in Crossref's reference-linking program. Pre-2000 literature has low coverage.
- **Full-text links ≠ open access.** `has-full-text` means a full-text URL is registered; access may still require a subscription. To restrict to genuinely open-access content, use `directory:DOAJ` (limits to DOAJ-indexed journals). There is no universal `is_open_access` filter in the Crossref API.
- **`crossref_search_works` sort options are fixed.** Valid values: `relevance`, `score`, `is-referenced-by-count` (citation count), `published`, `published-print`, `published-online`, `deposited`, `indexed`, `created`, `updated`, `references-count`. Arbitrary field-level sort is not supported.
- **Rate limits are soft.** The polite pool provides priority access but not guaranteed throughput. High-volume batch workflows should space requests.

## Decisions Log

### Answered questions

- **Polite-pool mailto — env var or hardcoded server contact?** → `CROSSREF_MAILTO` env var. Rationale: server operators may differ from the codebase author; env var lets each deployment supply its own contact without a code change.
- **Citation graph traversal — multi-hop or single-hop?** → Single-hop only (`crossref_get_references` returns one level). Rationale: multi-hop traversal with configurable depth grows O(N^k) in upstream calls, burns rate-limit budget, and the agent already has the DOIs it needs to chain calls itself. Let the agent decide traversal depth.
- **DataCanvas for large search result sets?** → Initially yes (opt-in via `CANVAS_PROVIDER_TYPE=duckdb`), later removed. Rationale: the spillover was wired in but no `dataframe_query`/`dataframe_describe` consumer tool was ever added, so the `canvas_id` handle was dead output. Crossref works are categorical bibliographic metadata — the workflow is search-then-resolve-a-DOI, not aggregate-over-rows — so the integration was removed rather than completed.
- **Incoming citations — expose a tool?** → No. Crossref genuinely does not provide this data; there is nothing to wrap. Documented in Known Limitations and reflected in `crossref_get_references` description so agents know not to try.
- **`crossref_search_journals` and `crossref_search_funders` — separate tools or modes of one tool?** → Separate tools. Rationale: journals and funders are distinct entity types with different search fields, output shapes, and follow-up patterns; consolidating under a `mode` enum would obscure the difference rather than reduce surface.
- **Member and Type endpoints — expose as tools?** → No. Members (publishers) are administrative detail with low agent-workflow value; Type is an enum used as a filter input, not a queryable entity. *(Member portion superseded 2026-07-13 — `crossref_get_member` was added; see Reversals. Type still stands.)*
- **Resources — add any?** → No. Crossref records are live-fetched; there are no addressable stable URIs the server owns. Tool surface is self-sufficient.
- **Journal/funder paging — extra inputs on the existing tools, or dedicated works tools?** → Extra inputs (`offset`, `works_offset`) on the existing tools. Rationale: each tool already returns both lists in one response, so splitting the works retrieval into its own tool would widen the surface without removing a call, and would strand the existing `include_works` shape. Two independent offsets on one tool cost less than four tools.
- **Cursor paging for the journal/funder works sub-resources?** → Yes, as `works_cursor` / `nextWorksCursor` on both tools. Offset paging reaches under 2% of a large corpus (Nature's 446,507 works, NSF's 559,023), and the alternative — `crossref_search_works` with an `issn:` / `funder:` filter — costs a tool switch mid-pagination and, on funders, answers a narrower question, since the sub-resource rolls in registry descendants and the filter does not. The works list stays a secondary surface on a tool whose primary result is the name search, which is why the cursor is another input on the existing tool rather than a tool of its own. *(Deferred at 0.3.0; the deferral's own rationale is what reversed it — see Reversals.)*
- **Cursor and offset on the works sub-resources — precedence rule or refusal?** → Refusal (`works_cursor_offset_conflict`), matching `cursor_offset_conflict` on `crossref_search_works`. Crossref rejects the pair outright, and a silent precedence would page a caller through a list they did not ask for while their other input sat unused. The guard keys on `works_offset > 0`, not on the field's presence: the input carries a schema default of 0 that no handler can tell from an omitted field, and 0 is the start of the list and is never transmitted, so every combination in which an offset would actually be spent trips the guard and none that would be silently dropped escapes it.
- **What ends a cursor walk?** → An empty page, not an absent token, on every cursor surface this server exposes. Crossref keeps returning a `next-cursor` past the end of a list — verified on `/works`, `/journals/{issn}/works`, and `/funders/{id}/works` — so relaying it verbatim loops a caller forever. `nextWorksCursor` and `nextCursor` are alike withheld once a page comes back empty, which keeps "no continuation field means the list is exhausted" true across both paging modes and all three tools. The guard keys on the page's item count, the quantity that says the walk is over; `totalResults` describes the query and stays at its full value on an exhausted page, so it cannot serve.
- **Does an exhausted walk need more than an absent token?** → Yes on `crossref_search_works`, no on the two sub-resource works lists, and the asymmetry is a property of the payloads rather than of the paging. `works` is the entire result of a works search, so an empty page with nothing said about it renders as blank text for a client reading only `content[]` — absence of a field it never sees is not a signal it can act on. The sub-resource tools always still render the journal or funder record that page was about. So the works search carries a `notice` on every empty page, naming which of the three causes applies: a query nothing matched, an offset past the end of a list that did match, or a completed cursor walk. The guard keys on the page's item count, which is what makes a page empty; `totalResults` only separates the causes, and gating on it alone left the two commonest empty pages unexplained on both result surfaces.
- **Retry policy for a request timeout?** → Non-retryable at the deadline-expiry throw site; the contract entry stays retryable for 408/504. A timeout is the one transient class whose cost is bounded by this server's own deadline rather than by how fast the upstream answers, so every retry costs the maximum instead of the typical: four attempts at the default `CROSSREF_TIMEOUT_MS` is ~40s of deadline plus ~7s of backoff, which can outrun an MCP client's own request budget and leave the recovery hint unread. Deriving `maxRetries` from `CROSSREF_TIMEOUT_MS` was the alternative and was rejected — `withRetry` takes one budget for every error class, so tying it to the timeout would also cut the retries that let a 429 or a 5xx clear. The split belongs at the throw site because that is where the two costs are distinguishable, and `retryable: false` is the mechanism the stock predicate already honors, so no custom `isTransient` is needed.
- **Continuation offsets past the route ceiling — hand them out and let Crossref reject, or withhold?** → Withhold, but say so. A `nextOffset` a client cannot spend reads as "more is retrievable this way" and costs a round trip to disprove. Withholding it silently is the opposite failure: absence of the field otherwise means "the list is exhausted," so a ceiling-truncated page reads as complete, and because the offset is never handed out the caller never trips `offset_too_large` and never reads the recovery that names the escape hatch. The ceiling page therefore carries a `notice` stating the cap, the true total, and the route that reaches the rest.
- **Ambiguous `include_works` on funders — reject, or return the works with a source label?** → Reject, matching the journals guard. Rationale: consistency between the two tools matters more than the extra round trip, and a label only helps clients that read `structuredContent` — a content-only client would still see an unattributed works list. Refusing puts the identifier in the caller's hands either way.
- **Ambiguity measured against the returned page, or the upstream match count?** → The match count. Rationale: a page-length test is defeated by `rows: 1` and by any `offset` landing on the tail of a list — the response then holds exactly one record and the guard passes, restoring the silent pick it exists to prevent. The match count is the only measure of whether the caller actually chose the record whose works come back.
- **Recovery hints for the shared service's throws — per-tool contract entries or literals at the throw site?** → Both, from one table. `ctx.recoveryFor` is unusable from inside `CrossrefService`: it resolves against the *calling* tool's declared reasons and returns an empty object for any tool that has not declared the one being raised — no hint on the wire, no error, nothing to notice. So the service builds the hint itself. The contract entries are still declared on all seven tools, because a contract that omits the failures a tool can actually raise is wrong regardless of who populates the wire, and `errors[]` is compile-time and linter metadata rather than a `tools/list` payload, so the duplication costs a caller nothing. Drift between the two is prevented by construction: `upstream-errors.ts` holds one entry per reason, the tools spread it into `errors[]`, and the service reads `recovery` off the same object at the throw site.
- **Adopt the framework's `fetchWithTimeout` for the transport?** → No. It would fix timeout classification by construction, but it throws on non-2xx and returns only a 500-byte body string, so the 400 branch could no longer parse Crossref's `validation-failure` body into a filter-key hint, and every 404 — a routine outcome the handlers turn into `doi_not_found` — would be logged at error severity. Its two load-bearing mechanisms are cheap to replicate and were: identity-matched `TimeoutError` aborts and a transport `catch` that unwraps `.cause`. Revisit if the helper ever hands the `Response` back to the caller.
- **Markup in reference free text — blanket strip, raw passthrough, or something narrower?** → Narrower: a bracket is stripped only when it is recognizable as markup by shape, by sitting inside a markup region, or by an element name on a closed allow-list. The two extremes each fail on measured data — raw passthrough leaves markup on four fifths of the sampled fields that carry a bracket, and a blanket strip cleans those but deletes cited URLs, Miller indices, DOI fragments, and bracketed notes. Neither ambiguity is resolvable from the bracket alone, so the rule resolves it from the tag's shape and its element name. That keeps the governing constraint intact — an ambiguous angle bracket must not cost the reader content — while cleaning 2,467 of the 3,063 affected fields in a 49,700-work sample and deleting nothing. The full account is under Text normalization above.
- **The entity table — the names a sample shows, the full HTML5 set, or a dependency?** → The full set, self-contained. A measured 11,900-work sample turns up 49 distinct names, 44 of them outside the five the decode started with and almost all appearing once or twice; a table sized to that sample is a table the next sample outgrows, which is the failure the five-name version already demonstrated. The spec's set is closed, stable, and normative for what a publisher can deposit, so the whole of it is the right table — 2,125 names packed into 20 KB of source, against a runtime dependency that would carry a resolver, a release cadence, and an API surface for a lookup that is one `Map.get`. The full account is under Text normalization above.
- **A structured citation deposited whole into a free-text field — enumerate the JATS vocabulary, or match the envelope?** → Match the envelope, the same way a MathML formula is matched: end to end, all or nothing, every tag inside it removed. Enumerating the ~60 elements a `<mixed-citation>` may contain would admit a long list of bare ordinary words (`year`, `source`, `comment`, `size`, `label`) whose brackets are reader content everywhere else, and would still miss whatever the vocabulary defines next. The envelope resolves the ambiguity at the field level instead — inside one, nothing was typed by hand — so the allow-list stays short and any child element is handled whether or not it has been seen.
- **JATS citation elements observed bare, outside an envelope — admit them?** → The markup-only ones, yes (`etal`, `fname`, `article-title`, and the `surname`/`given-names`/`string-name`/`person-group`/`collab` siblings that share their shape); the bare ordinary words, no (`volume`, `year`, `source`, `comment`, `ref`). The split is the allow-list's second admission test, and `<ref>` is why it exists: its one occurrence in a 49,700-work sample is a paper title about Wikipedia's `<ref>` tag. Rarity alone did not decide it — `etal` (10 fields) is in and `volume` (3 fields) is out because one name can never be content and the other can.
- **A bracket that survives normalization on purpose — how should it reach a `content[]` reader?** → Escaped at the `format()` boundary, one rule over every kept bracket. `content[]` is a Markdown rendering of the same values `structuredContent` carries, so a renderer reads each of them a second time: it consumes a kept link as its children alone and loses the address, resolves the character reference a publisher escaped twice, eats the brackets around a cited URL, and pairs a deposited `*` with the `*…*` `format()` writes around a journal title. The seam is `format()` because normalization decides what a value contains and `structuredContent` is a contract over exactly that — a backslash written into the value would change the machine-readable surface to fix a rendering defect, while one written at the render boundary reaches only the surface that needs it. Escaping per class was rejected for the reason #55 gives for not rewriting a link to `text (href)`: the question belongs to every deliberately-kept bracket at once, and one rule at one seam is what answers it for a link, a cited URL, a Miller index, and a bracketed phrase together. The escape is conditional on measured grounds — 6,565 sampled reference fields carry an ampersand against 60 carrying a character reference, and 2,504 carry a `[` against 8 carrying a `](` — so it changes 0.125% of projected values and costs none of them a character. Machine-format values stay byte-exact: a reader copies them, and a backslash inside a URL breaks the copy. The full account is under Text normalization above.
- **An `<alternatives>` wrapper — enumerate the encodings, or pick one by position?** → Position: the first child carrying text, selected as a region the way a MathML formula is matched. The children are siblings with no marked primary, so preferring TeX over presentation MathML or the reverse would rank notations this server has no standing to rank and would need extending each time the vocabulary admits another encoding. A positional rule needs no such list — a text-free `<inline-graphic>` is passed over on that basis, and an unseen child element is covered by the same rule. Matching the closed pair rather than the name is also what protects the reference surface, where `alternatives` is an ordinary word somebody could bracket.
- **The boundary an `<alternatives>` wrapper leaves — none, the conditional word boundary, or a block?** → A block, the outer edge a MathML region already gets, and the wrapper's rather than the selected child's. Consuming the region also consumed the boundary its own tags had been leaving, which glued the prose to the formula on the deposits that pack them together (`on a time scale$\mathbb{T}$with`). Leaving none keeps that. The conditional class is not a third option: measured over every wrapper in a 10,000-work draw it changes nothing at all, because the wrapper is nested inside a formula wrapper — `<inline-formula>` on all but one deposit observed, `<disp-formula>` on the other — and the conditional rule reads the characters actually adjacent to the region, which are that wrapper's tags. Evaluating it against the surrounding *text* instead would be a fourth separator class no other element uses, would need a backward scan past runs of tags — quadratic on an adversarial one — and would space a wrapped formula differently from a bare one. The block boundary costs a space before a comma or a hyphen in four of the seven values it changes, which is what a MathML region in the same position already renders today.
- **A Markdown block marker at the head of a rendered value — widen the shared escape, or scope it to the call site?** → Scope it, as a second entry point (`mdTextAtLineStart`) called from the one line that places a deposited value at column zero. Whether `#`, `>`, `-`, or `19.` opens a block is a property of the placement, not of the value: 1,201 of 328,920 sampled values open on one of those characters and nearly all are rendered mid-line, where they are inert, so a widened escape would put a backslash in front of the leading hyphen of every title starting with one and protect nothing. A wrapper local to `crossref_get_work` was the other option and was rejected for the reason the shared escape exists at all — a second escape rule living in one tool is how the seven renderings drift apart. Omitting it at a future column-zero call site is caught rather than silent: the cross-tool probe that already fails a tool rendering a value without the inline escape now opens on a block marker, and a rendered line beginning with the inline-only form of it fails there.
- **A link element — always keep its tag, always strip it, or check?** → Check, per occurrence. The tag is kept because the address can live in an `href`, and on the JATS-deposited fields it usually does not: a structured abstract deposits its URL, accession, or trial registration as the element's own text and repeats it in the `href`, so the tag protects nothing and puts a namespace-bearing XML tag in the middle of an abstract. The tags therefore come out where the element carries no attribute, where the `href` is a bare fragment addressing a place inside the publisher's own XML, or where the text already contains the `href` — verbatim or less its scheme, and no looser, since `www.`, a trailing slash, percent-encoding, and a resolver host are all parts of an address rather than differences to be assumed away. Measured across 22,000 works on the JATS side and 12,000 on the reference side, that removes 56 opening tags and loses no address. Both outcomes are real: 31 elements in the same draw address something their text does not name, and those keep their tags. The full account is under Text normalization above.
- **`<formula>` / `<tex>` — leave the TeX wrapper in place?** → Strip it. The earlier call was that stripping trades XML noise for TeX noise, but the formula survives either way and the wrapper carries nothing: `<ref_formula><tex Notation="TeX">$\hbox{1}/f$</tex></ref_formula>` reads as `$\hbox{1}/f$`, a notation a reader can follow, against the same notation wrapped in XML. It joins tight for the reason a script does — a formula continues the token around it. 21 fields in the sample, the largest class remaining after the link elements.
- **An out-of-range author `offset` on a record that deposits no `author` field — add a notice?** → No. The offset did not cause the empty result, so an offset notice would misattribute it, and a coverage notice of the kind `crossref_get_references` carries is not warranted here: that one exists because the reference list is the tool's *entire* payload, so an empty one renders as blank text on `content[]`. `crossref_get_work` returns the whole record — title, container, dates, abstract — and a record with no author list is answered by the record itself, with `authors`, `authorCount`, and `offset` all absent together as the signal.
- **Bounding the author list — a cap on both tools, or paging?** → Paging on `crossref_get_work`, a per-work cap on `crossref_search_works`, both defaulting to 25. A bare cap on the single-DOI tool would need an arbitrarily large maximum to reach a 2,932-author record in one call, which paging does not; the search tool cannot page an array nested one level inside a list it is already paging, so the cap plus `crossref_get_work` as the named escape is the workable shape there. The default is set from the distribution rather than picked: across 1,000 recent journal articles p99.5 is 22 authors, so 25 leaves ordinary records untouched while still bounding the tail. Scoped to `author` alone — `funder` (max 71 sampled), `link` (max 4), and `subject` (empty on nearly every record) are orders of magnitude off the author tail, and `affiliation` is bounded as a consequence of bounding its parent.
- **A funder or affiliation Crossref names by ROR instead of by name — drop the entry, keep it blank, or carry the identifier?** → Carry it, as `ror`. Making `name` optional is what stops the crash, but an assertion left holding only an award number, or an affiliation left holding nothing, names no organization — the caller is handed an entry it cannot resolve, which is the failure in a quieter form. The ROR is the entry's whole identity in that deposit, so it is projected and it stands in for the name on both surfaces. Dropping the entry instead was rejected for the reason a bound is never applied silently: a funding assertion the record makes must not vanish from the response. ROR rather than every identifier in the array, because it is the one every nameless entry in a sampled draw carried and the only one ever seen alone, while the array's `DOI` entries merely restate the `doi` field.
- **A `null` date component — pass it through, coerce it, or omit it?** → Omit, and stop the read there. Crossref uses `null` inside `date-parts` for a component it does not know, which is the same fact a caller reads off an absent optional field, so reporting it as one keeps the two indistinguishable rather than inventing a third state. Coercion has nothing to coerce to. The read stops at the first unknown rather than continuing past it because the tuple is positional: a day whose month is unknown renders through `formatDateParts` as `2020-15`, stating a date the deposit does not make.
- **A source that names no date — skip the source, or answer with nothing?** → Skip it, and settle that once for every tool. The four date fields are read in preference order and the chain advances only where the current source names nothing at all: a `[[null]]` tuple is Crossref stating a component is unknown, the same fact an absent field states, so treating the field's *presence* as an answer reports no publication date for a record that carries one further along the chain. It does not advance on a coarser date, because the sources are different facts rather than one fact at four precisions — 580 of 6,000 randomly drawn works carry a `published` coarser than a source behind it, and completing one from the other would answer with the online date instead of the publication date. The order was previously spelled at each call site, in two spellings that disagreed on exactly the skipped-source case; it now lives in `resolveWorkDate` / `resolveWorkSummaryDate`, which take the record rather than a chain of its fields, so no call site has a chain to spell. `issued` stays exclusive to `crossref_get_work` — that is which sources a tool reads, a separate question from when the chain moves on.
- **Where the line falls between handling a sparse shape and letting the call fail?** → At what Crossref's deposit model permits. A shape the model permits is ordinary and is handled as the normal case; a shape it does not — a `null` in a string array, a license entry with no `URL` — is upstream corruption and is left to reach the output schema, which rejects it as a typed `ValidationError` naming the field. Writing a guard for the second kind would turn a corrupt response into a plausible-looking result, and there is no useful thing to put in the field's place. The record's own identity is unguarded on the same reasoning from the other end: `raw.DOI` is what makes a work record a record, so a fallback there would return something nothing downstream can resolve. Sampling sizes these shapes and never settles them — absence from a draw is not evidence a field is guaranteed, which is what the earlier required declarations assumed.
- **A custom `isTransient` predicate for `withRetry`?** → No. The retry waste was never the predicate's fault: it treats a non-`McpError` throw as transient, and every throw that reached it was unclassified. Classifying at the throw site fixes retry cost and the surfaced error code together, and one deterministic case that still lands on a transient-looking code (`malformed_response`) opts out through the contract's `retryable: false`, which the stock predicate already honors. A custom predicate would re-sort the same unclassified exceptions by shape, one layer too late.

### Corrections from API verification (v0.2 → v0.3)

- **`offset` is honored on all four journal/funder routes.** Verified by row identity, not status code — `/journals`, `/funders`, `/journals/{issn}/works`, and `/funders/{id}/works` each return different records at `offset=0` and `offset=2` with a stable `total-results`. A route that ignored `offset` would answer 200 with the unfiltered first page, so status alone proves nothing here.
- **The offset ceiling is not uniform.** The name-search routes accept `offset + rows` up to 100,000; the works sub-resources cap at 10,000 and say so in the rejection body ("Use the cursor parameter to page further into result sets"). An earlier single ~10K figure covered `/works` only.
- **The works sub-resources do support `cursor`.** `GET /journals/{issn}/works?cursor=*` and `GET /funders/{id}/works?cursor=*` each return a `next-cursor` token, so the 10,000 ceiling bounds the `offset` input alone and is not an upstream limit on how far either list can be read.
- **`GET /funders/{id}` accepts three identifier forms** — bare registry ID, percent-encoded full DOI, and full DOI with a literal slash — all returning the same record. The `funder_doi` validator had required the `10.13039/` stem, rejecting the bare form its own description documented before any request was made.

### Options declined

- **Multi-hop `crossref_get_references` with a `depth` parameter** → Declined. Exponential upstream call growth per hop, unbounded latency, and rate-limit risk disproportionate to the use case. Agent chaining is the right model.
- **`crossref_get_member` tool** → Declined. Publisher administrative metadata (member records) has minimal agent utility and would widen the surface with low-value data. *(Superseded 2026-07-13 — see Reversals.)*
- **`crossref_list_types` tool** → Declined. Work types are a closed enum (journal-article, book, book-chapter, etc.) better represented as an inline enum in `crossref_search_works`'s filter schema than as a separate tool call.
- **App tools** → Declined. No real-time human-in-the-loop interaction with Crossref data warrants the iframe/CSP overhead.
- **Instruction tool** → Declined. No recurring "how do I do X given my current state" pattern; this is a straightforward data-retrieval server.
- **Prompt templates** → Declined. Interaction patterns are not complex or recurring enough to warrant reusable prompts.

### Corrections from API verification (v0.1 → v0.2)

These items were wrong in the initial design. All were verified against the live API.

- **`select=` on `/works/{doi}` does not exist.** The API returns `parameter-not-allowed`. `select` works only on `/works` (search). `crossref_get_references` must fetch the full record from `/works/{doi}` and extract `reference[]` client-side — no shortcut is available.
- **Offset paging is capped at ~10K.** Requests with `offset + rows > total-results` (and approximately > 10K absolute) return a 400 validation error: "Use the cursor parameter to page further into result sets." The design's statement "Crossref uses `offset`/`rows` (not cursor)" was incorrect. Deep paging requires `cursor=*` on the first request, then chaining `next-cursor` tokens. `cursor` and `offset` cannot be combined.
- **`is_open_access` / `is-oa` filter does not exist.** The live API returned `filter-not-available` for `is-oa`. For open-access filtering, use `directory:DOAJ` (value must be uppercase `DOAJ`). There is no universal OA flag in the filter syntax.
- **Filter keys use hyphens, not underscores.** e.g. `has-abstract`, `has-references`, `has-full-text`, `from-pub-date`. The design's filter object description used underscore variants (`has_abstract`, `is_open_access`) which would produce API validation errors.
- **Sort field for citation ranking is `is-referenced-by-count`**, not "citation count". Additional valid sort fields: `score`, `relevance`, `published`, `published-print`, `published-online`, `deposited`, `indexed`, `created`, `updated`, `references-count`.
- **Tool description leakage fixed.** `crossref_get_work` original description included "prefer `crossref_get_references`" — meta-coaching directing the consumer. Removed. The incoming citations scope boundary is now stated as a fact ("use OpenAlex for full citation graphs") rather than a directive.
- **Error contracts, `format()` requirements, DOI validation, `fields`/`cursor` parameters** were absent from the initial design. Added under Input Schema Notes, Error Contracts, and `format()` Notes sections.

### Reversals

- **`works_cursor` threaded through both works sub-resources (2026-08-06).** Reverses "Cursor paging for the journal/funder works sub-resources? → Not in this release" (Answered questions). The deferral rested on `crossref_search_works` with an `issn:` / `funder:` filter being an adequate substitute; it is not. On funders the two sets differ by design — `/funders/{id}/works` reported 559,023 works for NSF against 454,467 through the `funder:` filter, because the sub-resource includes the funder's registry descendants — so redirecting a caller there past the ceiling answered a narrower question without saying so. The reach argument compounded it: offset paging covers under 2% of either Nature's or NSF's works list, which makes the ceiling the normal case for any large corpus rather than an edge. `crossref_search_works` remains valid for callers who want the filter's semantics; it is no longer the only route past 10,000.
- **`crossref_get_member` and `crossref_get_prefix` added (2026-07-13).** Reverses the earlier "Member and Type endpoints — expose as tools? → No" (Answered questions) and "`crossref_get_member` tool → Declined" (Options declined). The prior calls judged member records as low-value administrative detail; that under-weighted publisher identification as an agent workflow — "who publishes DOIs under prefix 10.1038?" and "how completely does this publisher deposit references/abstracts/ORCIDs?" The member record carries genuine signal (owned prefixes, DOI counts, per-work-type breakdown, per-category deposit coverage), and `crossref_get_prefix` resolves a DOI prefix to its owning member ID for a clean two-step lookup. The prefix response is honestly thin (owner name + member link only), so its output mirrors exactly that. Type-listing stays declined — a closed enum is better as a `crossref_search_works` filter value than a tool. Event Data (`crossref_search_events`, the third tool proposed alongside these) was dropped: the Event Data public API was permanently sunset on 2026-04-23, so there is no live upstream to wrap.
